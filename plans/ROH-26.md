## Context

The PDF extraction pipeline has two components that were calibrated against different source PDFs:

| Component | Calibrated Against | Coordinates |
|-----------|-------------------|-------------|
| **Generator** (`generate_sample_returns.py`) | IRS blank templates | Correct for visual alignment |
| **Extractor** (`mappings/form_1040_20XX.py`) | Sample filled PDFs | Different dimensions/positions |

This mismatch causes extraction failures on generated test PDFs:
- **2018:** Completely blank (y-coordinates ~87pts off)
- **2019:** Partial reads (refund "742" instead of "1,742")
- **2020:** Partial reads (total_tax "638" instead of "9,638")
- **2021:** Nearly all zeros (y-coordinates ~70pts off)
- **2022-2024:** Work correctly (likely calibrated more recently)

### Root Cause: Bbox Left Edge Truncation

When values are right-aligned at x=552 but the extractor bbox starts at x=534+, longer numbers get their leading digits cut off:

```
Value "1,742" right-aligned at x=552:
  "1" at x≈524
  "," at x≈531
  "7" at x≈538  ← Extractor starts here (x=534)
  "4" at x≈545
  "2" at x≈552

Result: Only "742" is captured
```

## Summary

Recalibrate all extractor field mappings (2018-2021) against the IRS blank templates to match where the generator places values. Add tolerance margins to handle slight variations. This unifies both components on a single coordinate source.

## Technical Approach

### Why This Approach

1. **IRS templates are the canonical source** — Real user PDFs generated by tax software generally follow IRS layout
2. **Generator positions are visually correct** — Values land in the right boxes
3. **Extractor should find values where they actually are** — Not where they were in arbitrary sample PDFs
4. **Single source of truth** — Eliminates coordination problems

### Alternatives Considered

| Approach | Pros | Cons | Why Not |
|----------|------|------|---------|
| Fix generator to match extractor | Quick | Generated PDFs look wrong | Visual correctness matters for validation |
| Wider extraction boxes | Quick fix | May capture adjacent fields | Doesn't fix vertical misalignment |
| OCR-based extraction | Robust to layouts | High complexity | Over-engineered for current needs |

## Major Changes

### Extractor Mapping Structure

Each year's mapping file needs coordinates that match where IRS templates place values:

**Current (wrong for 2018):**
```python
"wages": {
    "page": 1,
    "bbox": (547, 128, 594, 141),  # Calibrated against sample PDF
    ...
}
```

**After (correct for IRS template):**
```python
"wages": {
    "page": 1,
    "bbox": (461, 41, 575, 51),  # Matches IRS blank template
    ...                          # Left edge expanded for tolerance
}
```

### Calibration Process

For each year, use pdfplumber to find exact field positions:

```python
import pdfplumber

with pdfplumber.open("test-data/blank-templates/f1040--2018.pdf") as pdf:
    page = pdf.pages[1]  # Page with income fields

    # Extract text with positions
    for char in page.chars:
        if char['text'] in '0123456789':
            print(f"Digit at ({char['x0']}, {char['top']}, {char['x1']}, {char['bottom']})")

    # Or use visual debugging
    im = page.to_image()
    im.draw_rect((461, 41, 575, 51))  # Test bbox
    im.save("debug_2018_wages.png")
```

### Tolerance Margin Strategy

Instead of tight bboxes, use wider boxes that accommodate value length variation:

```python
# Old: Tight bbox (prone to truncation)
"bbox": (547, 128, 594, 141)  # Width: 47pts

# New: Wider bbox with left margin
"bbox": (500, 128, 594, 141)  # Width: 94pts (47 extra on left)
```

This ensures 6-digit numbers (e.g., "125,189") are fully captured.

## Risks & Considerations

- **Historical samples may break:** The old sample PDFs have different coordinates. Options:
  - Accept that only IRS-layout PDFs are supported
  - Create secondary "sample PDF" mappings as fallback
  - Auto-detect PDF source and choose mapping

- **Real user PDFs vary:** Tax software may not match IRS template exactly
  - Mitigation: Use wider bboxes with tolerance margins
  - Future: Add confidence scoring and manual correction flow

- **Calibration is manual:** Each year requires visual verification
  - Mitigation: Create helper script with visual debugging
